# Arena 四模型实验：方法与答辩说明

主报告采用老师原题 **Who Wrote It? Identifying LLMs from Their Responses**，个人作者为 Haodong Huang。旧 UltraFeedback 实验及报告仍然保留。

## 我们到底在预测什么？

输入是回答文字（或问题、或两者）；标签是该回答来自哪个固定模型版本。四个类别是 Claude Sonnet 4、GPT-4.1、Grok 3、DeepSeek V3。实验不判断回答真假，也不判断人类与 AI，不证明能识别这些公司的所有模型。

原始数据是 135,634 场 Arena 对战，并不是 135,634 个独立问题。只选择四个明确的非 thinking 版本，以减少思考模式差异的干扰。清洗后有 9,643 个模型侧回答，四类各为 2,201–2,774 个；这比旧实验 4,254 个回答多，但任务也从三分类变成了四分类，准确率不能直接当作同任务提升。

## 为什么不是把整份 140k 都塞进去？

原始数据包含其他模型、其他语言、多轮历史、重复提问、thinking 变体等。增加这些数据可能让分类器学会语言、任务、思考方式等捷径。当前选择英语、第一场评估、严格单轮的 user/assistant 记录，先定义清楚预测目标，再保留所有符合条件的样本，没有根据分类难易筛选。

## 怎样防止泄露？

同一个会话、相同问题、近似问题、相同回答，通过传递关系合并成组，再划分训练/验证/测试。测试集有 1,466 个回答；验证集 1,442 个；训练集 6,735 个。

全量数据只用于不依赖类别或成绩的重复检测，这是明确披露的清洗步骤。分类器的词表、TF-IDF、标准化、类别权重只从训练集学习。模型名称和公司名称在问题与回答中都被替换掉。评分、胜负、时间、任务标签不作为分类器输入。

## CNN 与 RNN 的区别是什么？

CNN 用宽度 3/4/5 的卷积捕捉局部文本组合，然后通过最大池化抓住任意位置的强特征。LSTM 属于 RNN，它按顺序计算每个 token 的上下文状态，再用 masked mean + max pooling 汇总。验证集选择了更宽的 CNN 和双向 LSTM。PAD 不能进入汇总，也不能当作真实的反向上下文。

CNN 读前 384 个回答 token；LSTM 读前 192 个。该结果比较的是两个训练方案，不能把差异完全归因于 CNN 与 LSTM 结构。每个架构内部的三种输入条件保持同样的回答预算。

## 怎样选择模型？

先以随机种子 1448 比较两个 CNN、两个 LSTM 候选。依据验证集 macro-F1 选择每个架构的方案，平手再看验证损失。然后用 1448、1449、1450 三个种子重复三种输入条件。优化最多 20 轮，连续 4 轮无验证提升则早停。

主要指标是 macro-F1，让四个类别同等重要；同时报告 accuracy、balanced accuracy、每类召回率、三个种子的波动，以及按测试组重采样的区间。测试组区间没有完整涵盖训练与模型选择的全部不确定性。

## 四个研究问题怎样回答？

- RQ1：只看回答，比较 CNN 和 LSTM，报告平均成绩与每类错误。
- RQ2：比较只看问题、只看回答、两者一起看。Arena 没有每题四模型完整配对，所以只看问题不保证刚好 25%；必须实际测量并讨论主题混杂。
- RQ3：非代码训练、非代码验证、代码测试；与训练总量和各类数量完全匹配的混合任务控制组比较。使用一个种子，是探索性的跨任务实验。架构方案沿用主实验的混合任务验证筛选，因此这里是“训练数据排除代码任务”，不能说全部超参数选择从未接触代码任务标签。
- RQ4：字符/词语 TF-IDF、结构统计、去除显式长度的结构统计、只保留词语的神经网络消融。格式消融同时改变 token 组成和截断范围，不能解释为某一个格式特征的纯因果作用。

打乱训练标签的 CNN 是负对照。若它也高分，需要检查泄露；低分则只是通过这一项检查，不能证明没有其他混杂。

## 展示时不要怎么说？

不要说“世界最好”“对任何 AI 都能识别”“softmax 就是真实来源概率”。不要把三分类旧成绩与四分类新成绩当作严格可比的提升。不要把 coding/non-coding 测试切片和真正的 domain holdout 混淆。详细数值以最新英文报告与 results/arena/summary.json 为准。
